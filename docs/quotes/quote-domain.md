# Quote Domain

Sprint 8 turns the preview configurator into a dealership sales surface: a
**completed configuration** becomes a **professional quotation** — priced by
the server, immutable forever, shareable and printable.

## Aggregate

```
Quote (aggregate root)
├── QuoteLine[5..n]        priced items (wheel, tyre, labour)
├── QuoteSnapshot (1:1)    the full Json snapshot payload, versioned
├── Customer               upserted per (tenant, email) when an email is given
└── SavedConfiguration     system-managed anchor, named `Quote WV-2026-000001`
```

The legacy `SavedConfiguration`/`Customer` relations predate Sprint 8 and
remain required FK anchors — the repository satisfies them inside the
creation transaction, so no migration breaks existing rows and no
placeholder data leaks into the domain.

## Lifecycle

```
        POST /api/quotes                 POST /:id/archive
 draft ───────────────▶ ISSUED ───────────────────────▶ ARCHIVED
                            │
                            │ POST /:id/duplicate  (re-price at today's book)
                            ▼
                        new ISSUED quote, fresh number
```

- `ISSUED` — content is **immutable**: lines, totals, customer, snapshot.
  The only write allowed is the `ARCHIVED` transition (`archivedAt` set).
- `ARCHIVED` — historical record; still readable, printable, shareable,
  duplicatable. Never deleted (soft-delete column exists but the API never
  deletes quotes).
- **Duplicate** is the answer to "same again, current pricing": it rebuilds
  the request from the source snapshot and issues a *new* quote under a
  fresh number. History is never rewritten.

## Quote numbers — sequential, atomic, collision-safe

`WV-<issueYear>-<sixDigits>` (e.g. `WV-2026-000001`), allocation rules:

1. The tenant row carries `quoteSequence` (additive migration, default 0).
2. Inside the quote-creation transaction the repository runs
   `UPDATE Tenant SET quoteSequence = quoteSequence + 1 … RETURNING`.
   PostgreSQL serialises that row lock across concurrent creators, so
   numbers are sequential and gap-light by construction.
3. The number formats from the returned counter and the **issue timestamp**
   (`getUTCFullYear`), so a year boundary flips the prefix naturally.
4. A `(tenantId, quoteNumber)` unique index backstops the counter: on a
   `P2002` collision (e.g. legacy rows) the whole transaction — counter
   increment included — rolls back and creation retries with a fresh
   sequence, up to `QUOTE_NUMBER_MAX_RETRIES = 3` before surfacing `500`.
5. The placeholder `WV-PENDING` in the service-built snapshot payload is
   overwritten with the allocated number before persistence — the snapshot
   always carries the truth.

50-way concurrent creation is covered by a unit test; every number is
unique, sequential and issued once.

## The immutable snapshot

`QuoteSnapshot.payload` (Json, `version: 1`) persists **everything needed to
reproduce the offer forever**, independent of later catalog or price-book
changes:

| Section | Content |
| --------------- | ------------------------------------------------------------------------------ |
| Identity        | `version`, `quoteNumber`, `issuedAt`, `validUntil` (issue + 30 days)           |
| Parties         | dealer (tenant id/name/slug), customer (name/email/phone), consultant          |
| Configuration   | the raw seven-field selection exactly as sent                                  |
| Vehicle         | id, manufacturer, model, variant, year, colours, **render metadata**           |
| Colour          | the exterior colour chosen                                                     |
| Wheel           | id, brand, model, finish, and the full size spec (diameter, width, bolt, offset, bore) |
| Tyre            | id, brand, pattern, and the full profile spec (width/AR/rim, construction, load/speed) |
| Asset references| the vehicle package asset URLs referenced at issue time                        |
| Pricing         | price list (id/name/kind/currency), priced **lines mirroring the rows** (same ids), subtotal, discount(s applied), tax (strategy code/name/rate/cents), total, currency |

Two invariants make the snapshot trustworthy:

- **Twin lines** — line ids are pre-generated by the service
  (`createStorageId`), so the snapshot's `pricing.lines` are literally the
  same ids as the persisted `QuoteLine` rows — snapshot and database can
  never drift apart.
- **Frozen reads** — payloads are deep-frozen server-side on the way out
  (`lib/deep-freeze.ts`), and `readSnapshot` shape-guards corrupt/legacy
  payloads to `null` instead of crashing views.

## Tenant isolation

Every read and write carries the tenant id: lists filter `tenantId`,
detail/duplicate/archive match on `id + tenantId` (a foreign id is a `404`,
never a leak), the sequence counter lives on the tenant row, and prices
resolve within the tenant's own price lists.

## Print & share (Sprint 8 scope guard)

- **Print** is the browser pipeline over a print-only document
  (`hidden print:block`, `aria-hidden` on screen): dealer branding, parties,
  package, line items, VAT, totals, prepared/validity dates, six T&Cs, the
  "not an invoice" disclaimer, reference number and a **QR placeholder**
  block (`data-qr-placeholder`) for Sprint 9's verification code. No PDF
  engine, no invoicing/payments/billing anywhere.
- **Share** transports: copy link (`?quote=<uuid>` deep link), mailto
  payload (subject+body RFC-6068 encoded), WhatsApp `wa.me` payload,
  plain-text clipboard payload — all built from the immutable detail, all
  degrading gracefully on denial.
