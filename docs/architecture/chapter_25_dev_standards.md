# Chapter 25 — Development Standards

## Code standards

- TypeScript strict mode enabled.
- ESLint and Prettier enforced.
- Functional components and hooks preferred.
- Shared domain logic should be tested and isolated.

## Repository conventions

- Feature-based or domain-based folder grouping.
- Clear naming for domain entities, UI components, and API routes.
- Documentation updated with every significant architectural change.

## Review standards

- Pull requests require architecture review for cross-cutting changes.
- All API contract changes must be reflected in documentation before implementation.
